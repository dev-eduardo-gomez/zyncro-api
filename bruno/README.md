# Cobrix API — Bruno collection

Manual requests against a running API. The source of truth for the API is still `contracts/openapi.yaml`; this collection only mirrors the endpoints that are implemented (or being implemented) so they can be exercised by hand.

## Setup

1. Open the `bruno/` folder as a collection in [Bruno](https://www.usebruno.com/): **`+` → Open Collection**, not **Open workspace**. This folder is a collection (it has `bruno.json`), not a workspace, so it has no `workspace.yml`.
2. Copy `bruno/.env.example` to `bruno/.env` (gitignored) and set the credentials of an existing user.
3. Select the `local` environment (`baseUrl` defaults to `http://localhost:3000`).
4. Start the database (`docker compose up -d`) and the API (`npm run start:dev`).

## Creating a user to log in with

There is no seed or user-management endpoint yet (#21). Create one by hand:

```bash
# from the repository root: print an argon2 hash for the password
node -e "require('argon2').hash(process.argv[1]).then(console.log)" 'your-password'
```

Then insert a row into `users` with that `email` and `password_hash` (for example with `npx prisma studio`). Fill `id` yourself: `@default(uuid())` is generated by Prisma Client, not by the database, so a direct insert without it fails with a null `id`.

```bash
node -e "console.log(crypto.randomUUID())"
```

`role` (`MAKER`) and `created_at` have database defaults and can be left empty.

## Flow

Requests chain through runtime variables, so run them in this order:

| Request | Sets |
|---|---|
| `Auth / Login` | `accessToken` (every other request inherits it as a bearer token) |
| `Customers / Create customer` | `customerId` |
| `Invoices / Create invoice` | `invoiceId` |

`Create customer` uses `{{$timestamp}}` in `taxId`, so it can be run repeatedly without hitting the `409` duplicate rule.

## Keeping it in sync

When a task adds an endpoint (payments in #5 T3, invoice listing in #5 T4), add its request here in the same change.
