# Issue #4 — JWT authentication and role-based access control

Objective: stateless JWT login and RBAC (`MAKER`, `CHECKER`, `ADMIN`) with Problem Details errors. Branch: `feat/4-auth-jwt-rbac` (from `dev`, PR targets `dev`). Delivery: `ask-on-risk`. Runner: Vitest (`npm test`, `npm run test:e2e`, `npm run test:int`). Mode: split (L19) — assistant writes all tests, domain and `schema.prisma`; user reviews them, runs migrations, writes adapters/application/infrastructure. Architecture: hexagonal. Risk: item 2 (security) — independent verifier + RDD review apply.

## Specs

- S1 — "Modelo mínimo `User` con rol (`MAKER`, `CHECKER`, `ADMIN`) y contraseña con hash."
- S2 — "Login que emite un JWT stateless; estrategia Passport JWT."
- S3 — "Guard de roles con decorador `@Roles()`."
- S4 — "Una ruta protegida responde 401 sin token o con token inválido."
- S5 — "Un usuario con rol incorrecto recibe 403 como Problem Details."
- S6 — "Las contraseñas nunca se almacenan ni se devuelven en texto plano."
- Out of scope (verbatim): "Multitenancy, refresh tokens y rate limiting (ver #7)."
- Contract (proposal, added to the issue body on 2026-10-21): `POST /auth/login` -> `{ accessToken, tokenType: "Bearer", expiresIn }`; JWT payload `{ sub, email, role, iat, exp }`; `GET /auth/me` -> `{ id, email, role }`; 401 login detail "Invalid email or password." for unknown email and wrong password alike.
